# Безопасное обслуживание серверов

Текущий этап реализует только диагностику и предварительный план. Удаление файлов, Docker prune, перезапуск контейнеров, изменение Xray и отключение клиентов отсутствуют.

Для локальных временных файлов панели доступен обратимый quarantine. Он перемещает только проверенные аудитом файлы в `backup/maintenance-quarantine` и поддерживает восстановление. Окончательное удаление отсутствует.

## Защитные гарантии

- Панель использует только `GET /admin/system/maintenance-audit` и `GET /admin/system/maintenance-servers`.
- Удалённый агент принимает авторизованный `GET /v1/maintenance`.
- Агент не получает Docker socket и возвращает `cleanup: false`, `restart: false`.
- При наличии активных сессий план помечается `blocked-active-clients`.
- При недоступной диагностике план всегда заблокирован.
- Диагностика серверов запускается вручную, а не при каждом открытии панели.
- Quarantine требует точную фразу `QUARANTINE`, restore — `RESTORE`.
- Произвольные пути, `..`, абсолютные пути, символические ссылки и файлы вне результатов аудита блокируются.

## Что анализируется

- использование файловой системы контейнера edge;
- доступная память, load average и uptime;
- число временных и ротированных log/backup-файлов в каталоге edge;
- сохранённое число активных сессий из статуса синхронизации.

Содержимое файлов не читается. Символические ссылки не обходятся. Сканирование ограничено 2000 элементами.

## Ограничения текущего этапа

Статистика файловой системы внутри контейнера может отличаться от полной статистики host-диска. Docker images, volumes и build cache намеренно не анализируются: Docker socket агенту не подключён. Для будущей очистки нужен отдельный минимально-привилегированный maintenance worker с allowlist, обязательным dry-run, блокировкой при активных сессиях и проверкой соединений после каждой операции.

## Zero-downtime rollout агента

Сначала обязательный dry-run одного узла:

```powershell
$env:DRY_RUN='1'
$env:ONLY_EDGE='relay-eu-am'
node scripts/install-edge-sync-agent.mjs
```

Установщик обновляет только `vpn-edge-sync-agent` командой Compose с `--no-deps`. PID Xray фиксируется до операции и обязан остаться тем же после неё. Затем проверяются `/health` и авторизованный `/v1/maintenance`. Массового rollout в установщике нет: `ONLY_EDGE` выбирает ровно один сервер.

Production использует pull-only reporting: агент отправляет snapshot в `POST /internal/edge/maintenance`, а панель читает сохранённые отчёты из `/data/files/maintenance-server-reports.json`. Открывать внешний доступ к порту агента `19222` не требуется.

Для TCP relay генератор Xray теперь добавляет локальный `HandlerService` API на `10085` и inbound tag `vless-tcp-in`. Применение этой части требует планового пересоздания Xray-контейнера; во время активных клиентских сессий автоматический rollout запрещён.
